# 裁剪为独立工作流平台

当前工作流执行引擎使用 MySQL、Redis 和对象存储，Elasticsearch、Milvus、etcd 和 NSQ 的依赖主要来自知识库、统一资源搜索及启动装配。按照已确认的裁剪方向，保留独立工作流的列表、创建、编辑、调试、发布和执行，移除知识库与统一搜索的运行依赖，并保留 MySQL、Redis 和 MinIO。

复用现有基于 MySQL 的工作流列表和独立编辑器，不重建整套跨资源搜索。工作流异步执行沿用进程内执行方式，不引入替代消息队列；移除搜索索引通知不能影响工作流创建和复制的业务结果。

## 产品边界

- 保留基础流程、HTTP、Python、大模型、子工作流、数据库操作和插件调用，以及数据库和插件的管理入口。
- 大模型节点可以调用插件和子工作流，但不能绑定知识库或读取 Agent / Chatflow 历史。
- 只保留轻量模式，不添加完整模式切换；不保留应用 / Agent 开发页、项目 IDE、知识库和会话类节点。
- 默认部署使用本仓库构建的前后端，避免继续运行依赖完整基础设施的上游镜像。

## 验证要求

- 不启动 Elasticsearch、Milvus、etcd 或消息队列，后端能够完成初始化。
- 独立工作流列表、创建、复制、保存、发布、删除和允许节点的执行正常。
- 知识库节点及大模型知识库绑定在服务端得到明确拒绝，不能只隐藏界面入口。
- 子工作流、旧画布和导入数据不能绕过能力限制。
- 已有业务记录保留；裁剪不需要清空数据库或删除存储卷。
